# Resume creator

## Purpose
"Make my resume like this" + a picture (or PDF) of any resume → Jarvis **copies that design exactly** (see *Exact replica engine* below) and fills it with the user's own details. Output: A4 **PDF**, PNG previews and an editable **HTML** file in `data/uploads/resumes/` (served at `/media/resumes/...`). Without an image it uses a fixed format: `elegant` (gold diagonal banner + photo, Venn skills), `modern`, `minimal`, `creative`, `executive`, `tech`. The older vision "describe-then-pick" analysis (`_resolve_design` / `_analyse_design`) is now only the fallback when the exact engine fails (the reply says so) or `RESUME_REPLICA=0`.

## Exact replica engine (`app/services/resume_replica/`, 2026-10-03)
Plan and rationale: `docs/plans/resume-exact-replica.md`. No vision-model call; everything is measured from pixels. First analysis of a design ≈ 60–90 s (fonts ≈ 45 s), then cached per file SHA-1.
1. **`ingest.py`** — image → page at 200 dpi (`PX_PER_MM`), viewer chrome/edge lines trimmed, PDF rasterised from vectors. Reports `src_dpi` and `partial` (screenshot of the top of a page).
2. **`measure.py`** — RapidOCR with the **English** recogniser (`data/models/en_PP-OCRv3_rec_infer.onnx`, auto-downloaded; the bundled Chinese one drops spaces). Per line: ink box (limited to its own OCR band — neighbours' ascenders inflate sizes at low dpi), fg/bg colour, stroke, swallowed bullets. Then structure: headings (keyword + consistent distinctive style, single-linkage groups, two-line headings merged, item titles that repeat a section word rejected), name/title, columns (heading x-clusters, separator = whitespace gutter no line crosses), sections, item roles (item_title / sub / meta / meta_right / body / list / subhead), a contact strip beside its heading.
3. **`plate.py`** — the background **plate**: the reference with every text glyph, the photo, and all content inside section areas erased, filled from a per-colour-region smooth background model (`_bg_model`, robust 2nd-order fit + masked residual correction so no ghost text/haze survives). Before erasing it cuts out transparent assets: each heading's decoration (box/underline/icon, text inpainted), bullets/icons left of lines, contact icons by type, timeline line + node, and measures bars (fill/track/level), dots, chips (outline vs fill), the photo frame (consensus circle/rectangle over 96 rays + the photo blob so no part of the reference person remains; rings kept). `plate2.png` = continuation background for page 2+.
4. **`fonts.py` / `fontmatch.py`** — library of the ~456 most popular Google Fonts (all weights, `data/fonts/gf/`, auto-download via `python -m app.services.resume_replica.fonts`) + installed Windows fonts + anything in `data/fonts/user/` (drop a paid font there to make it exact). Matching runs in headless Chromium canvases in 4 worker processes: candidates are drawn at the reference's own pixel size (same stem thickening), gamma 0.75, core-normalised, NCC + ink-mass + aspect; stage 1 regular/bold of every family, stage 2 all weights of the 10 best. Lower-case text is matched with letter-spacing locked to 0 and sized from its ink **width**; caps can be tracked. `_choose_families` keeps ≤ 3 families jointly.
5. **`pipeline.py`** — builds the spec (`app/memory/replica_docs/exact_<sha1>.json`, `SPEC_VERSION`; assets in `data/uploads/resumes/replica/<sha1[:16]>/`): styles per role key (`name`, `title`, `head<col>`, `item_title<col>`, `sub`, `meta`, `meta_right`, `body`, `list`, `contact`, `subhead`, `hcontact`) with family/weight/size/letter-spacing/colour/case/pitch, header slots, photo, columns, sections with decoration, tokens (ink-top → ink-top gaps: `head_first`, `title_sub`, `sub_meta`, `head_body`, `new_item`, `item_gap`, `sec_gap`) and graphics.
6. **`exact_render.py`** — `render_replica_html(c, d, photo_uri, scale)`: plate as page background, name/title/photo/header contact at measured positions (`data-fit` shrinks a longer name), columns flowing with the measured styles; every gap is converted to a CSS margin with the font's half-leading (`Styles.lead`). Headings use the decoration crop as a 9-slice `border-image` (hug = grows with the text, full = column width). The user's sections fill the reference's slots (projects take an empty Experience slot); sections the reference lacks go to the column where they fit (`_est_height`). Same editor DOM hooks as the legacy renderer (`section.sec.sec-<key> > h2`, `_f`/`_it`).
7. **`integrate.py`** — `create_resume` → `analyse_with_progress` (progress lines stream to the chat) → `replica_design(spec, previous)` = a legacy-compatible design (`layout: single_column`, `replica: {sha1}`, keeps `free`/`hidden_sections` of the same design) → `replica_note` (warns below 100 dpi / partial page). `_render_html` routes on `design["replica"]`; `_render_files` pins sections and keeps the measured sizes (≤ 8 % shrink only with a page target).
`scripts/replica_eval.py` renders any set of references into `data/uploads/resumes/replica_eval/index.html` (reference | replica | fonts).

**Editor = PDF, page targets, follow-up edits (2026-10-04, round 3):**
- *One layout engine for screen and print.* `_PAGINATE_JS` decides page breaks inside the page (a block that would cross the bottom margin moves to the next page behind an explicit `.pgsp` spacer — a spacer's height survives a print break, a margin would not; headings and an item's first line stay with what follows; the body ends on a whole page). There are no print-only layout rules any more (no `box-decoration-break`, no `break-inside`, page-2 background is the same absolutely positioned tile in both). All layout scripts (`_FIT_JS`, paginator, contrast guard) run after `document.fonts.ready` and set `body[data-ready]`; `_render_files` waits for it. The editor re-runs `window.__rbLayout` while you type.
- *Same scale:* `_render_files` returns the winning `scale`; `create_resume` / `editor_save` store it as `state["render_scale"]`, and `editor_page` renders with it. Changing **Fit N pages** in the editor now fits immediately (export) and reloads. Verified: word positions editor vs PDF differ by a median 0.36 mm (measurement offset), no different line breaks.
- *Page targets on exact copies:* the fit loop may go to scale 0.70 — `render_replica_html` maps scale ≥ 0.85 to whitespace only (gaps down to 40 %), below that also the type (to ~82 %); `data-mintop` is off while squeezing. Content condensing (LLM) only runs if that still doesn't fit.
- *Reference text in the background (it looked like "hallucinated" content and couldn't be removed by an edit, because it wasn't in the content):* OCR pieces of letter-spaced lines are merged (`_merge_spaced`), header text areas are cleared whole, the residue sweep finds spaced capitals ("B U S I N E S S"), the final OCR check removes single letters too, filled heading boxes are cleaned inside. Thin lines that run ≥ 60 mm across ≥ 2 sections (a timeline joining the headings, dividers) are design: `_long_lines` keeps them whole.
- "Internship" counts as experience; headings the vocabulary doesn't know become reusable slots.
- The editor page starts below the real toolbar height (`_EDITOR_FIT_JS`; the toolbar wraps to 2 rows on laptops).

**Robustness rules added 2026-10-04 (from a 42-dpi navy-chevron template):**
- *No reference text may survive in the plate:* glyph erase + halo erase + `_text_residue` (rows of ≥ 3 small marks that close into a text-shaped blob) + `_ocr_verify` (OCR the finished plate, wipe anything readable). Heading decorations drop leftover letters (only rules, big shapes and icons left of the text are kept) and text pixels become transparent or the box colour — never inpainted (inpaint smudges looked like scribbles).
- *Photos without a real face* (cartoon/illustrated avatars): `_skin_face` (largest compact skin-tone area in the top half, outside background regions) seeds the frame fit; a fitted frame that contains the whole picture blob wins (avatar on a light square → the square).
- *Trailing heading rules* ("Contact Me ———") are measured (`deco.rule`: colour from the core pixels, thickness, gap, length, `to_edge`) and drawn after the new text (`_with_rule`, flex row), so longer headings push the rule instead of running over it.
- *Placement:* a user section without a slot takes a vacant reference slot of the same kind (list↔list, items↔items) with that slot's heading style; reference slots carry `data-mintop` so on page 1 they never start higher than in the reference (JS in `_FIT_JS`). Margins are clamped ≥ 0.2 mm (no overlaps); a pitch outside 1.0–1.75 × font size falls back to 1.32 ×.
- *Contrast guard* (`_CONTRAST_JS` + `_bg_grid`): text that flows onto a different background (out of a dark sidebar onto white) switches to the most readable colour of the design's palette. Chips and text on filled heading boxes are skipped (`data-nc`).
- *Headings:* a keyword line with a date beside it is an item title ("Course Name … 2014-2017"); one-member style groups are rescued when the line stands apart (blur splits a sidebar's "Contact Me." / "About Me." into separate groups); `title_key` has fuzzy matching for OCR typos ("LANCUAGE").
- *Header:* the title stays on one line (shrinks to ≥ 75 %, then wraps) with its own background patch when a decoration sits beside it (`room` measured on the plate).
- *Skill bars:* rows are split at horizontal gaps (2-column grids), fill/track read from the bar's two ends, rendered by `_bar_grid_html` in the measured number of columns.
- *Editor:* `overflow:hidden` and the fixed page-2 plate apply only `@media print`; on screen the page-2 plate tiles down the body from 297 mm, so the editor scrolls and lines up. Education date and details are two separate `data-f` fields (a joined field made the editor save "CGPA" into the period again on every save).
- A missing/outdated spec (e.g. after a `SPEC_VERSION` bump) is rebuilt from `replica.path` / `data/uploads/<source>` on render.
- Later the same day: `data-mintop` only applies when the flowed position would land on a different background than the reference slot (otherwise short content would leave gaps); extra sections are placed by simulating each column top-down (slots at their reference tops) and use the design's *smallest* section gap; a vacant slot is reused only if the section fits there. Header room is "rule" (soft — a longer title covers it with the sampled background) or "hard" (photo/blocks — the title fits before it); obstacles come from non-background design elements, not region edges. The contrast guard only corrects text whose contrast is below 0.7 × that style's contrast in the reference (pale-on-colour titles stay as designed). Icons in the same column as the header-contact icons are erased too (their lines may be unreadable). Wide viewer overlays are filled column-wise (keeps a sidebar edge exact). With a page target an exact copy may shrink type ≤ 15 %.

## Flow
1. `chat_endpoint` runs an early intercept (after the note/WhatsApp flows, **before** media/DAG/complex-task checks, because pasted details are long multi-clause text): `resume_builder.detect_resume_request(prompt)` → kwargs, or `{"_list": True}` for "list resume templates". The result streams via `iterate_in_threadpool` and is added to `conversation_history`.
2. `create_resume(...)` (generator, progress lines then markdown):
   - **Design**: an image/PDF (and no explicit template) → the exact replica engine (above). Only if it fails, or for presets / follow-ups, `_resolve_design`: image → `_analyse_design` runs **two Groq vision calls in parallel** (`settings.GROQ_VISION_MODEL`): a style prompt (header/photo/font/skills style, plus a k-means palette from `_palette` so it picks exact hexes) and a focused layout prompt (section → column, heading/banner/Venn colours). `_apply_layout_answer` maps headings to section keys (`_TITLE_KEYS`). The result is merged over the closest preset (`_merge_design`) → `template`/`color` overrides → `_sanitize_design` (contrast fixes, every section gets a column).
   - **Content**: `_build_content` (gpt-oss-120b → 20b, JSON mode) → `_normalise_content` → `_drop_invented` (removes any sentence/bullet with a number the user never wrote, and contact values not in the source). Edits go through `_edit_content(old JSON, instruction)`. A colour/template-only change skips the LLM.
   - No details yet → saves the design with `awaiting_details` (30 min) and asks for them. The next message counts as details if `_has_details()` (email/phone/experience words/length), even without the word "resume".
   - **Photo**: an attached photo (labelled, or a close-up face with >12% face area) → used. "use the same photo" → `_crop_photo` cuts it from the reference (Haar face → `_grow_photo_box` to the flat border → VLM bbox → face-expanded). No photo → initials block.
   - **Render** `_render_files`: `_render_html` (fixed CSS formats, inline SVG icons/Venn/rings) → Playwright Chromium `page.pdf` (falls back to the msedge channel). The fit loop counts **real PDF pages** with PyMuPDF: it first moves sidebar-friendly sections from main to a shorter sidebar, then shrinks `--s` (down to 0.8). PNG previews come from PyMuPDF.
3. State is saved in `app/memory/resume_state.json` (design, content, photo, ref image, last PDF), so follow-ups work: "change the resume colour to navy", "use the modern template for my resume", "add AWS certification to my resume".

## Content fidelity & page limits (2026-10-02)
- **No invented jobs:** the prompt says projects ≠ jobs. `_finalize_content` turns any experience entry without an organisation whose role the user never wrote into a project (or drops it if it's already a project). Projects are `{name, tech, period, bullets, description}` and render like jobs (`_projects_html`).
- **Projects in an Experience slot:** with no real jobs, `_effective_design` moves projects into the design's Experience slot (even if the model also listed "projects" elsewhere), and the user's "EXPERIENCE (PROJECTS)" heading follows.
- **User's own structure wins:** `_user_headings` reads UPPERCASE headings from the text ("SUMMARY", "CERTIFICATIONS & ACHIEVEMENTS"; glued text like "CONTACTEmail" is handled) → `section_titles` + `section_order`. `layout_hint` ("LEFT COLUMN: …") → `_apply_layout_hint` + `pinned` (the fit loop never moves pinned sections). A heading covering two lists merges them.
- **Each fact once / no made-up sections:** `_finalize_content` drops highlights/competencies/interests/etc. that neither the design nor the user's text has, and removes items that repeat stronger sections (`_similar` word overlap). `_restore_dropped` re-adds, verbatim, any full sentence from an entry's own block that the (fallback) model silently dropped. The number guard (`_nums`) treats "30K" as 30,000.
- **Strict page count:** `_parse_pages` ("single page", "1 page", "2 pages", "one-pager") → `create_resume(pages=)` / `state["target_pages"]` / editor **Pages** select. `_fit_render`: shrink type (to 0.74) → `_condense_content` (LLM, only the overflowing column `files["long_column"]`, numbers copied verbatim) → `_TRIM_STEPS` (least important first, only in the overflowing column). The reply says what was condensed or trimmed.
- **Header `sidebar_photo`:** photo at the top of the sidebar, name and title on a light band (`colors.band`) over the main column (`.main-top`). Also `language_style: squares` and a `corporate` preset. The design cache key is `v3:`.

- **Layout polish (2026-10-02):** main column padding is 7/12/10/8mm (8mm gutter next to the sidebar, 12mm outer margin; mirrored for sidebar_right). Sidebar photo 29mm. The name band (`.main-top`) bleeds to the column edges with 6.5/5.5mm padding. Paragraph line-height 1.6, bullets 1.5. Contact/list icons sit in a box one text-line high, so they centre on the first line. Education shows degree / institution / "dates · grade" as spaced lines. When bars/dots/rings are followed by tags, the tags get an "Other technologies" sub-heading (`.sub-h`).
- **Measured small details (pixels, not guessed, not hard-coded):** `_measure_frame` finds the page inside the picture (rows/columns dominated by the design's own colours, so phone bars and viewer background drop out), then the coloured blocks (sidebar / header band) → `page_inset` [top, right, bottom, left] mm, counted only on sides a block runs along (<0.8mm = touching, >14mm = no block there). `_measure_band` samples the real colour of a light name band from the pixels (vision hexes for near-white tones are unreliable) and measures its gaps → `band_inset` [top, right, gap-to-sidebar] + `colors.band`. `_css_extra` applies them to `.side-bg` (fixed, so every page), the header, columns, footer and `.main-top`. Cached v3 readings get these added lazily, with no vision call. Presets stay at 0.
- **Pixel truth over vision guesses:** `_pixel_colors` takes page / side-column / header-band colours from the image (a side column on the page colour → no fill) and finds a vertical divider line (pixels clearly darker than the page) → `column_divider` plus the real `sidebar_width`, overriding the model's "equal columns". A near-page `primary` falls back to the heading colour so bars and markers stay visible. New keys: `header_accent: left_bar`, `column_divider`, `item_rules`, `skills_columns: 2`, `colors.header_bg`. "Overview" counts as the profile heading.
- **Templates only on request:** `_TEMPLATE_RX` needs "<name> template/format/style/…" or "template: <name>", checked in the first ~220 characters only. A word like "tech" in "tech stack" no longer replaces an uploaded design. Colour requests are checked in that same request part only.
- **Order rules:** with an uploaded design, the design's section order wins. The user's text order is used only when they spelled out a column layout (`layout_hint`). Projects only take the Experience slot if that slot comes before them (not an empty placeholder appended later).

## Design vocabulary (what a reference image can map to)
- `layout`: sidebar_left / sidebar_right (coloured narrow column), **two_column** (equal white columns), single_column. `bottom_sections` = full-width strip after the columns (e.g. a contact row).
- `header`: diagonal_banner, full_band (+ **`header_shape`** flat / wave / curve / diagonal → `_shaped_header_html`, SVG band with a lighter under-wave), centered, left_plain, sidebar_name. `photo_position` left/right/center, `photo_ring`, `name_align`.
- **`footer_shape`** none / wave / curve / bar, plus `decor` none / circles / dots. Both are `position:fixed` divs so they repeat on every printed page. They **must use an SVG background image (`_svg_bg`)**: Chromium does not repeat fixed elements that contain an inline `<svg>` (verified 2026-10-02).
- `heading_style` adds square_icon / dot markers; `language_style` bars / dots / text; `colors.track` for bar tracks. Older saved designs get defaults from `_STYLE_DEFAULTS` in `_sanitize_design`. The newer CSS lives in `_css_extra`, so the old formats render as before.
- Preset **`wave`** = this vocabulary as a fixed format. The layout vision prompt reports `equal_columns` and `full` rows; `_apply_layout_answer` turns them into two_column / bottom_sections.
- Fit loop extras: `_balance_columns` (two_column: measure every section once and move sections greedily so both columns end at similar heights). A lone bottom strip on page 2 is folded into a column. The loop keeps the **best** attempt: one page at a readable scale (≥0.8), otherwise a page 2 that's ≥20% full with the most even columns.

## Visual editor (/resume/editor)
- Open it from the **✏️ Edit text, sections & layout** button in every "resume ready" reply, the paperclip menu → **✏️ Edit Last Resume**, or say "edit my resume" / "open resume editor" (`detect_resume_request` → `{"_editor": True}` → `open_resume_editor()`, which also opens the browser). A concrete change ("add Docker to my resume") still goes through the AI `instruction` path.
- `editor_page()` renders the saved resume with `_render_html(..., edit=True)`. The `_EDIT` contextvar makes `_f(path, value)` emit `<span data-f="experience.0.bullets.2" contenteditable>` and `_it(path)` mark list items. Normal PDF renders are unchanged (no editor attributes). Name/title upper-casing is CSS (`.up`), so edits keep the real case.
- Page JS (`_EDITOR_JS`) collects every `[data-f]` `textContent` into the content JSON and POSTs `/resume/save` (`app/api/resume_router.py` → `editor_save`). Hover controls ＋ ↑ ✕ send `op` (`_apply_op`: add a template item after / move up / delete). The toolbar sends `template`, `color`, `photo` (via `/upload`), `remove_photo`, `add_section` (`_ITEM_TEMPLATES`) or `instruction` (AI edit). These save and reload the page. **Save & export PDF** (or Ctrl+S) sends `export: true` → `_render_files` → returns the PDF link.
- Enter is blocked (single-line fields) and paste is plain text. The red line marks each A4 page break. Clearing a field's text deletes that item on save (`_normalise_content` drops empties).
- **Undo / redo / duplicate (2026-10-04):** one history for everything. Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z and ↶ ↷ work in both modes, including while typing in a resume field (the browser's own undo is replaced: `beforeinput` historyUndo is intercepted). A *local* step is a JSON snapshot of every `[data-f]` text plus the free design (`snapshot()`); typing makes one step per burst (new field or a pause > 1.2 s). A *structural* step is `{srv: id}`: every `/resume/save` that changes content/design/photo/page target/render scale (item and section ops, template, colour, photo, AI edit, page fit) stores the state from before it in `app/memory/resume_undo.json` (`_undo_push`, last 40) and returns `snap`. Undoing it posts `restore_snap`, which first stores the current state (so redo works) and then reloads. The history is kept in sessionStorage across the editor's reloads and only reused when the page's `RB.rev` (`_state_rev`: hash of content+design+photo) matches. **Ctrl+D** (or ⧉ in the hover controls / element panel) duplicates the selection: a shape → copy; anything inside a `[data-item]` (bullet, entry, skill…) → a real content duplicate (`_apply_op` `dup`, not for whole custom sections); other text → a free text box with the same computed style, glyphs placed exactly 4 mm lower-right (measured with a Range); the photo → an image shape (`RB.photo`); a coloured/bordered box → a rect. **＋ Text box** copies the resume's body text style (the computed font-family/size/weight/colour/leading/tracking/case that covers the most characters, headings and name excluded) into the shape (`ff`, `weight`, `size`, `lh`, `ls`, `pad: 0`) and opens it for typing.
- **Templates keep their own design (2026-10-04):** `state["tpl_designs"]` maps a template key (`_tpl_key`: preset name, `copy:<sha12>` for an exact copy, `image` for a VLM-read design) to `{design, render_scale}`. Switching (editor `template`, or a chat "use the X template") stashes the outgoing design with everything added to it (free layer: shapes, text boxes, styles, palette vars, colour swaps; hidden/arranged sections) via `_stash_design`, and brings back the target's saved design, or a fresh preset. The content (the person's details, custom sections) is shared by all templates. The template list shows "📷 Your copied design". A copy made before this existed is rebuilt from the cached analysis of `state["ref_image"]` (`_ref_copy_design`, no new analysis). `tpl_designs` is part of the undo snapshots.
- **Colour mode (🖌 Colours, 2026-10-04):** click any colour on the page, then choose its new colour; it changes everywhere that colour is used. Picking (`colourAt`): a text glyph under the pointer (caretRangeFromPoint + the character's rect) gives that text's colour; otherwise it walks `elementsFromPoint`: SVG fill/stroke, `<img>` pixel, background image (background-size/position/repeat mapped), 9-slice `border-image` (slice/width mapped), border, background colour. Image pixels are the most frequent colour in a 5×5 window, snapped to `RB.raster_pal`. Swaps are `free.recolor = [[from, to]]` (editing an already swapped colour edits its swap). The shared runtime (`_FREE_RT_JS` `recolor()`, run after `applyStyles`) swaps computed CSS colours (colour, background, borders, SVG fill/stroke/stop-color, colours inside gradients and SVG data-URI backgrounds) in the editor and in the PDF alike. User shapes are not touched. An exact copy's raster art (plate, heading boxes, icons, glyphs: `exact_render.asset_files`) is recoloured server-side by `resume_replica/recolor.py`: pixels near the colour shift fully, anti-aliased edges are unmixed against the image's dominant colours/white/black (p + a·(dst−src)), and other dominant colours are left alone. `_uri()` and the contrast-guard grid apply the swaps via the `_RECOLOR` contextvar. A swap touching a raster colour saves and reloads; CSS-only swaps are live. On an exact copy, the toolbar's main colour picker swaps the most-used saturated colour. Undoable, per template.
- **Section headings are editable** (`_sec` wraps them in `_f("section_titles.<key>")`). `collect()` only writes a heading the user actually changed, so untouched default titles don't pin `content.section_titles`. Hovering a section in Text mode shows ↑ ↓ ⇄ ✕ (`#rb-sctl` → `sec_op`).

## Free design (editor 🎨 Design mode, added 2026-10-03)
- **Toolbar:** ✍️ Text / 🎨 Design toggle, **＋ Insert** (line, curved line, arrow, rectangle, rounded box, ellipse, triangle, diamond, hexagon, pentagon, star, wave band, curve band, text box, icon, image), **＋ Text box**, ↶ ↷ undo/redo, and a **🎛 Panel** with three tabs: *Selected* · *Page & colours* · *Sections*. "Add section" also has **✚ Your own section…**.
- **Design mode:** click anything (a text span, heading, photo, header band, column, icon or svg) to select it. Drag moves it (CSS `translate`, stored in mm). Handles resize (`width`/`height`; the photo keeps its ratio, Shift frees it) and rotate (Shift snaps 15°). Del hides, arrows nudge 0.5 mm (Shift: 5), Ctrl+D duplicates (see above), Esc deselects, and double-click edits a text box. The panel sets font, size (pt), colour, B/I/U/caps, align, spacing, line height, background, border, corners, padding, opacity, shadow, position, size and layer. For pictures it sets shape (circle/square/rounded/ellipse/hexagon/diamond/pentagon/triangle/star via `clip-path`), size, zoom, pan and B/W. **Apply to: All like this** writes a group rule instead (e.g. every project bullet: `[data-f^="projects."][data-f*=".bullets."]`).
- **Lines:** quadratic curves. The yellow mid handle is the on-curve midpoint (`mx,my`; control = 2·mid − (p1+p2)/2), so dragging it bends the line. Shapes support colour, thickness, dash, arrows, fill/none, opacity, rotation, flip, "behind text" (`z: back`) and position in mm.
- **Page & colours:** overrides 14 palette CSS vars (`--primary`, `--side`, `--heading`…, live), heading/body fonts (`_FREE_FONTS`, Google Fonts loaded on demand), global text size (`text_scale`, multiplies `--s`), and every layout key of the design vocabulary (`design_set` → `_design_set`, validated against `_DESIGN_CHOICES`, reload). It also lists hidden elements (Show) and has Reset all.
- **Sections tab:** reorder ↑↓, move to the other column ⇄, hide/show, delete custom sections, add a custom section (title + bullets/paragraphs/tags/plain list + column). Ops go through `_section_op`: it writes the effective column lists back into the design, adds `hidden_sections`, and pins every section so the fit loop keeps the arrangement.
- **Data:** `design["free"] = {styles: {key: {css}}, groups: {selector: {css}}, vars, fonts, text_scale, shapes: [...]}`, cleaned by `_clean_free` (property whitelist, no `{};<>\`/`url(`, shape key/type whitelist, images must be existing local files). Custom sections live in `content["custom_sections"] = [{id: custom_N, title, style, items}]` (`_custom_sections`); `_effective_design` puts any unplaced one in the main column. Hidden sections: `design["hidden_sections"]` (`_section_html` returns ""). Every `/resume/save` call sends `free`. Design changes autosave (700 ms debounce) without a reload.
- **One renderer for editor + PDF:** `_free_html` emits font links, `<style id=rb-free-css>`, `<div id=rb-free>` and `_FREE_RT_JS`. That script resolves element keys, applies the styles inline (`!important`) and draws the shapes, in both the editor and the Playwright PDF render. Element keys are anchor + relative path: `f:<data-f path>`, `i:<data-item>`, `s:<section key>`, `l:<landmark>` (photo, name, headline, header, aside, main, sidebg, footer…), then `/tag.classes:n` steps that skip editor-only nodes. So the PDF needs the same anchors: when `free` has styles/groups, `_render_html` uses `_EDIT = "mark"` (data-f spans and data-item attributes, nothing editable, no placeholders). **Designs without `free` render byte-identical to before** (verified on all 8 presets + the saved design).
- Shapes are absolutely positioned in mm from the page top-left (`body{position:relative}` when shapes exist), so y > 297 lands on page 2 (verified). With shapes present, `_render_files` pins all sections (no column moves), but a page target can still shrink the type (`--s`).

## Gotchas
- **Exact replica:** font identification uses a `ProcessPoolExecutor` (Windows spawn): a test script must have an `if __name__ == "__main__":` guard (uvicorn is fine). Bump `pipeline.SPEC_VERSION` when the spec/plate format changes (cached specs are rebuilt). A chat colour request doesn't recolour an exact copy (the reply says so); the editor's 🖌 Colours mode and its main-colour picker do (see *Colour mode*); the editor's ⇄ column move has no effect on it (the reference fixes the columns) — everything else in the editor works. A horizontal contact strip in the reference is rendered as a vertical contact list. An OCR line that mixes two colours (e.g. a teal title + grey dates on one line) gets one blended colour. References below ~60 dpi give approximate sizes/fonts (the reply warns). Debug: `REPLICA_DEBUG=1`.
- Routing is **order-based** on both sides: whichever artifact is named first wins (`isResumeRequest` in App.jsx, `_OTHER_ARTIFACT_RX` vs `_NOUN` in the backend). Resume details contain "email", "presentation skills", "slides" etc. The old "any PPT word → PPT" check sent resume requests to `/ppt/create`.
- Fallback models sometimes drop the name/headline → `_guess_name` / `_guess_title` recover them from the user's text. The content prompt forbids pronouns (the model guessed "he" from a name).
- Fit loop (`_render_files`): `_placement` materializes every section into a column first, then moves sections from the longer column to the shorter (never back: `moved` set), then shrinks `--s` to 0.8 and keeps the best attempt (see Design vocabulary).
- The word "resume" collides with media ("resume the music") and task-resume. `_MEDIA_RX` bails out, and creation needs a verb+noun / "resume like this" / template-or-colour+noun. PPT/cover-letter/email prompts are excluded (`_OTHER_ARTIFACT_RX`).
- The small VLM alone often answers "single_column". The second, focused layout prompt is what makes sidebar detection reliable. Don't drop it.
- Chromium print: the sidebar background is a `position:fixed` div (repeats on every page). Column padding uses `box-decoration-break: clone` so page 2 has top padding.
- Testing burns Groq TPM quickly (429s). `_llm_json` retries and falls back to 20b.
- Free design: transforms don't apply to inline boxes, so the runtime adds `display:inline-block` when a moved/rotated/sized element is inline. A group or element style keyed on a `data-f` span only reaches the PDF because of `"mark"` mode, so don't drop that branch from `_f`/`_it`. `_edit_content` / `_condense_content` copy `custom_sections` back if the LLM drops them. A new main colour (`_apply_color`) clears the palette var overrides for primary/accent/heading/side/tint/track. Template switches swap whole designs (see *Templates keep their own design*).
- Editor overlays (`#rb-ctl`, `#rb-sctl`, `#rb-selbox`, line points) are absolute children of `<body>` (position:relative), so they're positioned with `brect()` (relative to the body box), not page coordinates.
