# PowerPoint generator

## Purpose
"make a ppt on X" → a designed .pptx on the Desktop (`<Deck_Title>.pptx`, `_2`… if taken), with streamed progress. Follow-ups ("on slide 3 …", "make it dark", "undo") edit that deck in place. Engine v6: no fixed templates; every slide is laid out at render time from its content and image shapes.

## Flow — create (`ppt_tool.ppt_create` → `ppt_studio.create`, a generator)
1. `ppt_content.split_request`: command line · pasted body · "Attached Context" (text of attached pdf/docx/txt/md) · `[ATTACHED_FILE]` paths (images, `.pptx/.potx` template, design-reference image when its description says theme/colours/reference/"like this").
2. Understand before designing: `repair_text` restores structure lost in copy-paste ("OverviewEvent:" → new line, "Features:Engine:" → new line, ". Label:" → new line; real camel-case names like KarmaSkill/MoSPI/iGOT are kept because they occur elsewhere). `split_instructions` / `_is_instruction` pull sentences about the deck itself out of the content, wherever they sit and however they start. Examples: "both of the images uploaded have to come under prototype section in slide 2", "first image on slide 3 and second on slide 5", "make 6 slides", "use a dark theme". "Label: text" lines and sentences about users uploading things stay content. `parse_instructions(lines, n_images, titles)` resolves:
- the slide: "slide 2", "second slide", "slide two", "the solution slide" (by title);
- which images: "both/all", "first image", "image 2";
- the section: "under the prototype section".

Unresolved image sentences go to `interpret_image_instructions` (LLM, given the slide titles). The section reaches the architect ("make that the gallery section") and the slide (`image_section`). The composer uses that section as the image gallery and creates the pill if needed. Gallery items beyond the image count stay as text under the screenshots. Follow-up edits can move images too ("move the screenshots to slide 3 under the architecture section").
3. `detect_profile` → purpose (`hackathon`/`academic`/`business`/`general`) + density (`light` = normal deck with little text, `balanced`, `dense` = hackathon). "N slides" → exact count (3–30).
4. Content:
   - **Architect (rich pasted content):** when `needs_architect` (paragraph-style slides, > 45 words), `architect_slides` asks the LLM, 2 slides per call, to *restructure* each slide into a `sections` slide (lead + titled groups: cards / list / steps / stats / fields / table / gallery captions + one highlight band) or a title slide with a details panel. It keeps the user's wording and adds **bold** key phrases. `extractive_ok` rejects any slide that brings in words or numbers not in the user's text (→ deterministic `sections_fallback`). `_missing_parts` retries once when labelled parts were dropped. After that, `_complete_from_source` guarantees nothing is lost: a still-missing part either replaces the condensed card it belongs to with your full wording (≥ 50 % token match), joins the group of the same name, or is appended as its own group. Tables are normalised first: the model sometimes sends `items: {header, rows}`. `deck_facts` passes product/team names so the title slide uses the product name.
   - **Strict:** `parse_user_slides` recognises "Slide N: …" blocks (line or inline), markdown `#` headings, `Title:/Subtitle:/Notes:/Image:/Layout:/Chart:` keys, bullets, "Head: text", "Group:" columns and `|tables|`. If every slide has content, the text is used **verbatim** and `infer_kind` + `apply_structure` only pick the layout (stats from numbers, timeline from dates, process, comparison…). Density then follows the user's word count, not the purpose.
   - **Partial:** titles-only slides are locked and the LLM fills just the empty ones.
   - **Generated:** `generate_deck` makes an outline (story rules + kind catalogue), then content in parallel chunks of 3 (Groq 120b → 20b on 429). `_flatten` repairs the model's nested JSON.
5. Images: explicit instructions win ("images in slide 2 only" → all there). Vision captions (`GROQ_VISION_MODEL`) are used only for images with no description and no instruction. Assignment order: logo (name/description) → every slide · "slide N" / cover / closing hints · strict `Image:` hints · LLM outline index · keyword overlap. Then `_rebalance` moves images off layouts that can't show them (table/chart/timeline/comparison).
6. Theme: `ppt_designer.resolve_theme` (13 curated themes; topic + purpose + instructions + "dark/light" + theme names; legacy `PERSONALITIES` names still work), or `extract_theme_from_image` → `_reference_theme` (keeps the reference's accents on a clean white canvas).
7. Render: `DeckRenderer` (own design) or `ppt_template.TemplateFiller` (user template). Deck spec saved to `data/ppt_decks/state.json` with a 10-step undo history.

## Layout engine (`ppt_designer.py`)
- Text is measured with the real Windows TTFs (PIL widths + OS/2 line heights via fontTools). `fit_size`/`_list_fit` pick the largest size that fits and never break a word; blocks sit at an optical centre (`_vpos`).
- Kinds: title, agenda, section, content (list / cards / 2-col grid / lead+list / statement), cards, stats, process, timeline, comparison, table (native), chart (native, editable), quote, image, gallery, closing.
- Images by aspect ratio: portrait/square → full-height bleed panel; landscape → framed at native aspect (no crop); panorama → band; several → justified rows (no crops). Any crop uses a saliency window (`_best_window`). webp/EXIF/huge images are normalised into `data/ppt_decks/img_cache`.

## Anti-hallucination for AI-written decks (`ppt_research.py` + `ppt_content.ground_slides`)
Long generated decks invented statistics, dates and quotes, contradicted themselves and repeated points. Generated content is now grounded and fact-checked:
1. **Research (zero LLM tokens, ~15 s):** `plan_queries` uses query templates per purpose. `gather_sources` pulls Wikipedia (API, entity-ranked: "Renewable energy in India" before "Energy transition") plus web search (`ddgs`, ≤ 2 searches in parallel with backoff) and fetches the pages.
2. **Facts:** `extract_facts` keeps *verbatim* source sentences that are on-topic, self-contained (no leading "It/This") and carry figures. It is deterministic, so the extractor cannot hallucinate. Off-entity facts are capped when the topic names an entity.
3. **Outline:** gets the facts (ids) plus rules. Data kinds (stats/chart/table/timeline/quote) are allowed only when cited facts contain the data, and they are banned outright when no facts exist. Each slide gets 2–4 unique `points`, which stops repetition. A short outline is continued ("slides k..N") instead of shrinking the deck.
4. **Content:** each chunk sees only its slides' facts (planned ids plus keyword-retrieved ones) under `_GROUND_RULES`: every figure, date, named report or quote must come from those facts, otherwise the point stays qualitative. Empty slides are retried one by one, and the planner's `goal` text is never pasted onto a slide.
5. **`ground_slides` audit:** every number, % , money amount, year, chart value, quote and URL must appear in the facts or the user's text (`audit_slide`). Flagged slides get one targeted LLM repair, and whatever still fails is removed deterministically (`scrub_slide`: clause → item → kind downgrade). After that come cross-slide de-duplication and fact-id stripping, and the sources go into each slide's speaker notes.
6. **Edits:** `_llm_edit`/`_llm_new_slide` receive relevant facts plus the same rules, and rewritten slides are re-audited. The pre-edit deck and the instruction count as known numbers.
7. **Free-tier budget:** `_llm_json` paces calls per model (8k tokens/min each), balances long decks over 120b/20b, and uses `reasoning_effort="low"` for copy-style work. On a daily cap (200k tokens/day per model) it skips that model, then falls back to Gemini (`gemini-3.8-flash` → `3.5-flash` → `3.5-flash-lite`). When everything is capped, `ppt_create` says so instead of running the legacy engine.
- No network means no facts, which means a qualitative deck where the audit strips any figure not in your prompt. Say "no research" or "offline" to skip research.

## Composite slides (`ppt_composer.py`, kind `sections`)
Reference-grade pitch layout (the look of top SIH idea decks):
- **Layout:** compact title and a bold lead with accent key words. Section pills sit over tinted icon cards (pastel family led by the theme accent; icons are Segoe Fluent glyphs rendered to PNG by `icon_png`, matched by `icon_for` keywords).
- **Other bodies:** steps, stats tiles, key–value fields, native tables, lists.
- **Images:** framed screenshots in a right panel with numbered captions (`justified_rows(cap_h=…)`, no crops).
- **Highlight band:** a "Why we stand out" band at the bottom.
- **Layout search:** `render_sections` tries image-panel widths 34/40/46 %, 1/2/3-column masonry, band vs folded, and normal vs compact cards. It picks the arrangement with the largest font that fits (`PPT_DEBUG=1` prints the choice, `=2` every candidate).
- **No empty space:** card grids use `_balanced_rows` (5 → 3+2, each row stretched to full width). `_masonry` packs sections into balanced columns (exhaustive for ≤ 8 sections, keeping reading order). `_fill` then shares each column's free height between its sections up to `_stretch_cap`, so cards grow with their content centred, and all columns end on the same baseline.
- **Images adapt:** image slides use mode `images`. The right column holds a pill, then the screenshots at full column width in their natural aspect (`image_block`, 1..n rows, never cropped), then text sections that flow under them. `eval_images` tries every split of sections between the columns and every row count. It scores balanced columns and larger screenshot area, and searches image-column widths of 30–58 %.
- **Cleanup:** one-card sections are folded into the previous group, sections restating title/lead are dropped, and an "Overview" one-liner becomes the lead.
- **Title slides with details** use `render_title_sections`.
- **Grid by deck mix:** decks that are mostly composite use a tight grid (0.42in margins) with a footer bar. Mixed decks keep the normal margins and footer.
- **Other layouts:** `**bold**` markup is stripped for every other kind (`_deep_plain`).

## Template mode (`ppt_template.py`)
- **format:** `analyze_format` finds a fixed submission format (sections with guidance prompts, form fields, e.g. the SIH idea PPT). Every section is kept with its heading; each prompt is answered under its own label. Form fields and slots (team name…) are filled only from the user's text, never invented, and unknown ones stay as in the format. Instruction slides are dropped.
- **clone:** sample slides are cloned (`clone_slide`, rels remapped) and their text/pictures replaced, keeping the runs' formatting (`write_text`).
- **layout:** a template with no slides (`.potx`) → its layouts' placeholders are filled.
- Fitting honours inherited sizes (layout/master `_run_size_and_font`) and paragraph spacing. It scales runs proportionally, and boxes grow only down to the next shape (`_limit_bottom`, e.g. a footer bar).

## Flow — edit (`ppt_edit` → `ppt_studio.edit` → `ppt_content.apply_edit`)
Deterministic first: delete / move / swap slides, exact title/subtitle ("…to 'X'"), `replace "a" with "b"`, images (attach + "slide N", remove, left/right side, logo), theme/colour/dark/light, font, layout change ("make slide 4 a timeline"), add slide (verbatim if content given after ":"). Anything else → LLM edit of only the target slides ("change ONLY what is asked"). "undo" restores the previous version. If the file is open in PowerPoint it saves `_v2`.

## Entry points
Chat keyword (chat.py: edit detection runs **before** create and needs an active deck; `.pptx/.potx` attachments → `template_path`) · router `ppt_create(user_prompt, style, purpose, template_path)` / `ppt_edit(edit_prompt)` · REST `/ppt/create` (positional args unchanged), `/ppt/build` (legacy `PresentationBuilder`), `/ppt/extract-theme`, `/ppt/styles`.

## Gotchas
- `ppt_tool.py` (~2.7k lines) is now mostly the legacy v5 engine: `_ppt_create_legacy` is only a fallback when v6 throws, plus `/ppt/build`, `PERSONALITIES` and `extract_theme_from_image`.
- Fixed-format decks keep headings unless the heading is a placeholder ("IDEA TITLE") or the user renames it (`replace_title`).
- Window-layout routing skips "slide N / ppt" sentences, so "put the image on the left of slide 3" isn't a window snap.
- Visual check: export slides with PowerPoint COM (`Slide.Export(path, "PNG")`); fonts must exist in `C:/Windows/Fonts` for exact fitting (falls back to a width heuristic).
